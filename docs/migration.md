# Перенос прежней установки

Этот сценарий выполняет агент после начального вопроса о прежних панелях и обязательного обследования независимо от ответа. Цель — сохранить понятное пользователю поведение сети, а не просто скопировать JSON.

## Инвентаризация

Сохраните штатный backup роутера и приватный snapshot Entware на компьютере. Проверьте процессы, init/cron, активный core, фактически объединённую конфигурацию Xray, DNS/sniffing, политики устройств, используемые порты, доменные/IP/CIDR-правила, GeoIPSET, native-профиль, состояние ручного выбора и расписания.

В Xray несколько файлов с `routing` не обязательно объединяют правила: для используемого нами формата последующий документ заменяет предыдущий. Анализируйте эффективную конфигурацию, а не только привычный `05_routing.json`.

Скачанные рабочие конфиги содержат секреты. Храните их в отдельном локальном каталоге с ограниченными правами, вне Git checkout и синхронизируемых публичных документов. Не выводите полные outbound, URL подписки, ключи, UUID, HWID и RCI-токены в чат.

Для предварительного локального анализа:

```sh
python installer/migration_inventory.py --input ./private-work/router-snapshot --output ./private-work/migration-report.json
```

Помощник читает JSON/JSONC, находит последний документ маршрутизации и выделяет только простые прямые правила доменов/IP в кандидаты. Составные условия, нестандартные входы, GeoSite/regexp, блокировки и proxy-правила остаются на ручную проверку агента. Отчёт ничего не применяет и сам содержит пользовательские адреса — его нельзя публиковать. Ошибки чтения обязательно разбираются, а не трактуются как отсутствие правил.

## Решение пользователя

Покажите краткий инвентарь и спросите, какой результат нужен:

1. Перенести совместимые настройки и заменить прежнюю панель.
2. Сохранить прежнюю установку для возврата, отключив её службы.
3. Начать новую настройку; удалить выбранные старые компоненты после успешной проверки.

Отдельно уточните перенос исключений и направления трафика, устройств, источника серверов и предпочтений. Если пользователь не знает, предложите сохранить поведение и объясните найденные различия. Не удаляйте неизвестные файлы и существующие backup по широким маскам.

Две панели не должны одновременно переписывать один Xray, watchdog или firewall. «Сохранить рядом» обычно означает закрытый архив и отключённую службу; действующий параллельный стек требует отдельных конфигов, портов, hooks и оценки ресурсов.

## План до переключения

Объясните конкретно: «Найдены такие службы; эти домены/IP сейчас идут напрямую; эти устройства используют VPN; перенесём выбранные настройки, отключим такую старую службу, проверим одно устройство и сохраним возврат». Укажите несовместимую логику и действия, которые потребуют перерыва сети. Применение начинается после понятного согласования этого плана.

Сопоставляйте смысл правил: `domain:` включает поддомены, `full:` — один hostname; CIDR и порты нельзя превращать в общий доменный обход. При конфликте direct/proxy или различии scope спросите пользователя и покажите эффект. GeoIPSET действует до Xray и может обходить его правила; это особенно важно для режима «VPN для всего, кроме исключений». Правила из подписки могут конфликтовать с выбранным режимом — их нельзя молча считать независимыми.

## Секреты и идентичность подписки

Если используется HWID, сохраните именно существующий идентификатор до первого запроса подписки. Новый HWID может занять дополнительное устройство у провайдера. Панель поддерживает предварительное локальное заполнение `subscription-client.json`; формат сверяйте с выбранным релизом. Не переносите в нашу панель чужие JWT/session-cookie, `user.json` и базы пользователей механически. Создайте собственный вход.

Пароли и URL серверов остаются локально. Перед переносом старого пользовательского файла получите согласие на его использование; если пользователь запретил чтение конкретного файла, это ограничение сохраняется. Обновление подписки не должно заменять рабочие данные текстовой ошибкой или создавать новые идентификаторы для обхода лимита устройств.

## Переключение и возврат

Для сохранения существующего рабочего XKeen/Xray готовьте `prepare_bundle.py --panel-only`; `install.sh` принимает его с `--migration-reviewed` и не меняет core. Если стек не совместим, нужен отдельный согласованный план обновления/переноса, а не `fresh` поверх неизвестных конфигов.

Отключите только обнаруженную и согласованную службу старой панели, сохраните её config/data и команды восстановления. Через новую панель импортируйте выбранный источник, совместимые исключения и настройки; затем проверьте реальные маршруты, DNS, HTTPS, устройства и сохранение после перезапуска. Удаление старых файлов выполняется только по согласованному allowlist после успешных проверок и сохранённого backup.

При неудаче остановите новую панель, восстановите snapshot и прежнюю службу/выбор сервера. Проверьте восстановление доступности и маршрутизации; наличие файлов backup само по себе не подтверждает откат. Проблему опишите по безопасным метаданным без секретных конфигураций.
