# Подпись выпусков

Панель ставит обновление только тогда, когда контрольные суммы выпуска подписаны ключом автора. То же проверяет установщик (`installer/prepare_bundle.py`).

## Зачем

Файлы выпуска лежат на GitHub. Тот, кто получит доступ к репозиторию, может заменить и файл панели, и `SHA256SUMS` рядом с ним — суммы сойдутся. Подпись делается на компьютере автора ключом, которого на GitHub нет. Подменённый выпуск панель не установит.

## Что подписывается

Файл `SHA256SUMS.sig` в выпуске. В нём одна или несколько строк, каждая — подпись Ed25519 в base64. Подписывается текст из трёх частей: строка `xkeen-panel release checksums v1`, тег выпуска и точное содержимое `SHA256SUMS`. Тег входит в подпись, поэтому суммы одного выпуска нельзя выложить под другой версией.

Выпуск принимается, если хотя бы одна строка сделана хотя бы одним из ключей, встроенных в панель. Открытые половины ключей записаны в `internal/releasesig/keys.go` и в `installer/release_signature.py`; тест следит, чтобы списки совпадали.

Ключей два: основной и запасной. Запасной нужен, чтобы выпустить обновление и заменить список ключей, если основной потерян или попал в чужие руки.

## Где хранить закрытые ключи

- Вне репозитория и вне GitHub: не в секретах CI, не в облачной папке, не на роутере.
- Основной — на компьютере, с которого подписываются выпуски. Запасной — на отдельном носителе, который лежит отдельно от компьютера.
- Файл ключа — одна строка. Её нельзя вставлять в чаты, заметки и письма.

Инструмент печатает только открытую половину ключа.

## Как выпустить версию

1. Отправьте тег. CI соберёт файлы и `SHA256SUMS` и опубликует выпуск. Пока подписи нет, панели этот выпуск не предлагают.
2. Соберите те же файлы у себя из того же коммита и той же версией Go и Node (команды — в `.github/workflows/release.yml`).
3. Скачайте `SHA256SUMS` из выпуска.
4. Подпишите, сверив суммы с локальной сборкой:

   ```bash
   go run ./cmd/release-sign sign -key <папка ключей>/main.key -tag v3.1.0 -sums SHA256SUMS -compare build
   ```

   Если сумма в выпуске отличается от локальной, подпись не создаётся. Разберитесь в причине, прежде чем подписывать.
5. Проверьте подпись ключами, встроенными в панель:

   ```bash
   go run ./cmd/release-sign verify -tag v3.1.0 -sums SHA256SUMS
   ```

6. Загрузите `SHA256SUMS.sig` в тот же выпуск.

Подпись запасным ключом добавляется к файлу второй строкой: та же команда `sign` с `-key …/spare.key -append`.

## Если ключ потерян или украден

1. Создайте новый ключ: `go run ./cmd/release-sign keygen -dir <папка вне репозитория> -name main2`.
2. Замените его открытую половину в `internal/releasesig/keys.go` и `installer/release_signature.py`, удалив прежнюю.
3. Выпустите версию и подпишите её запасным ключом: установленные панели доверяют ему и примут обновление, а новая версия уже не доверяет утраченному ключу.
4. Создайте новый запасной ключ и добавьте его следующим выпуском.

## Старые выпуски

У выпусков, опубликованных до введения подписи, файла `SHA256SUMS.sig` нет. Панель их не предлагает. Установщик принимает такой выпуск только с явным параметром `--allow-unsigned-panel`.
