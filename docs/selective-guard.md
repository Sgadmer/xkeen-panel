# Выборочная блокировка при потере VPN

### Переключатели в панели Mihomo

В **Настройки → Защита VPN** находится общий kill switch. По умолчанию он включён. Если VPN-маршрут недоступен, Mihomo блокирует соединение. При выключенной защите для такого маршрута разрешён запасной прямой выход. Адреса с явным правилом «Напрямую» продолжают идти напрямую.

В разделе **Сервисы** режим **Kill switch** по умолчанию — **Всегда включён**. Защита такого сервиса действует и при выключенном общем переключателе. **Как в настройках** следует за общим переключателем и показывает его текущее значение. **Всегда выключен** разрешает этому сервису запасной прямой выход при отказе VPN.

Эти правила обрабатывает работающий Mihomo. При полном отключении перехвата продолжают действовать независимые сетевые фильтры, в частности установленный фильтр адресов Anthropic API. Его состояние показано в карточке Claude.

В карточках Mihomo **Автовыбор** направляет распознанные адреса сервиса через пул **Все локации**. Роутер выбирает доступный VPN-сервер по времени отклика. Steam изначально работает **напрямую**. Можно назначить ему VPN, как и любому другому сервису. В карточке можно выбрать страну, свой пул, конкретный сервер или прямой выход. Для Claude доступны только VPN-маршруты.

После обновления старой панели откройте **Сервисы** и один раз нажмите **Применить** в блоке **Автовыбор для сервисов**. Карточки с прежним вариантом **По правилам роутера** получат исходные маршруты. Если вы уже выбрали сервер, пул или прямой выход вручную, панель сохранит ваш выбор.

### VPN по списку блокировок

В **Настройки → Режим VPN и сервисы** можно включить маршрутизацию по двум существующим базам Re:filter. Панель читает раздел `REFILTER` из `geosite_refilter.dat` и `geoip_refilter.dat`. На этой странице видны число доменных правил, число IP-префиксов и время последнего изменения применённого списка.

Claude с назначенным VPN сохраняет свой маршрут. Ручные исключения, явные маршруты остальных карточек и локальная сеть сохраняют приоритет над списком. Для совпавшего домена Mihomo использует основной VPN из раздела **Серверы**. Известное имя вне списка открывается напрямую. Для соединения без распознанного имени Mihomo проверяет IP-префиксы. Это позволяет нескольким сайтам на одном IP иметь разные маршруты. Автор Re:filter включает в набор также сервисы с региональными ограничениями. [Описание источника](https://github.com/1andrevich/Re-filter-lists)

После обновления исходных файлов на роутере панель подхватывает изменения автоматически. При ошибке чтения продолжает действовать последняя применённая версия. Выключение режима восстанавливает прежнюю политику профиля.

У KeeneticOS 5.0 есть режим «Эксклюзивный маршрут» для списков DNS. Маршрут указывает на подключение роутера. При его недоступности адреса из списка теряют доступ, а остальные продолжают использовать свой обычный маршрут. В список можно добавить домен с поддоменами, IPv4 и IPv6. Прошивка требует, чтобы клиент использовал основной профиль подключения и DNS роутера. Браузер с собственным DoH может обойти такую классификацию. [Руководство Keenetic](https://support.keenetic.com/hero/kn-1013/en/51150-dns-based-routes.html)

Xray сохраняет названия узлов и групп в своей конфигурации. Для выбора такого узла в эксклюзивном маршруте нужен соответствующий сетевой интерфейс KeeneticOS. Штатный компонент Proxy client поддерживает SOCKS5. Совместимость локального SOCKS-входа, UDP, IPv6 и выбранной прошивки проверяется до применения маршрута к устройствам. [Штатный proxy-клиент Keenetic](https://support.keenetic.com/hero/kn-1013/en/49443-proxy-client.html)

### Защита входящих сетей Anthropic и синтетических адресов

`installer/strict-guard.sh` предназначен для схемы с локальным перехватом Xray. В рабочей конфигурации путь к скрипту — `/opt/sbin/xkeen-panel-guard`. Команда `apply` ставит перед остальными правилами `filter/FORWARD` и `filter/OUTPUT` запрет по адресу назначения. Он охватывает опубликованные входящие сети Claude API и Console `160.79.104.0/23`, `153.61.224.0/22` и `2607:6bc0::/48`. Это работает независимо от того, видит ли роутер доменное имя. Перед развёртыванием и после объявления изменений сверяют список с документацией Anthropic. Веб-приложение и сторонние ресурсы могут использовать дополнительные адреса. [Входящие сети Claude API и Console](https://platform.claude.com/docs/en/api/ip-addresses)

В панели откройте **Сервисы → Claude / Anthropic → Включить фильтр API**. Панель ставит встроенные скрипты, запускает `apply-api` и перечитывает обе таблицы через `check-api`. Этот режим использует только три опубликованные сети. Тот же процесс можно запустить из папки проверенного комплекта командой `sh install-claude-guard.sh install`. При совпадающих файлах запуск восстанавливает порядок правил. Если в файлах уже есть другие изменения, установка останавливается и сохраняет их. Хуки загрузки и обновления netfilter повторно применяют только режим API. Полная проверка маршрутов сервисов имеет собственный статус.

Вариант с выборочной выдачей FakeIP также использует диапазоны `198.18.0.0/15` и `2001:2::/48`. Скрипт закрывает оба диапазона. Их использование для обычного обмена внутри локальной сети несовместимо с этим вариантом. Перед включением сверяют оба диапазона с планом адресации. [Документация FakeDNS](https://xtls.github.io/en/config/fakedns.html)

`check` проверяет фактическое положение правил в ядре и завершает работу с ненулевым кодом при ошибке хотя бы в одной адресной семье. Правила срабатывают на любой протокол и порт. Адреса управления, обычные DNS-запросы и соединения за пределы защищённых сетей сохраняют свои прежние правила. `check-policy` принимает на stdin JSON со списком селекторов из панели. Для проверки DNS нужен модуль выбранной схемы. Его отсутствие означает, что защиту доменных запросов подтвердить нельзя.

Файлы `installer/S01xkeen-panel-guard` и `installer/99-xkeen-panel-guard.sh` предназначены для `/opt/etc/init.d/` и `/opt/etc/ndm/netfilter.d/` соответственно. Команда `stop` в init-скрипте оставляет правила в ядре. Установка этой пары не активирует перехват FakeIP или условный DNS.

### Что проверяет развёртывание

- Каждая защищённая зона получает синтетические A и AAAA. HTTPS/SVCB и CNAME не выдают реальные адреса, позволяющие обойти маршрут. Приложения с собственным DoH, DNS-кешем с реальными записями, зафиксированными адресами или сторонними серверами требуют отдельной проверки. Для клиента Claude с сетевым доступом исключительно к выделенному HTTP-прокси защищаются и запросы к неизвестным сторонним адресам.
- Независимый DNS роутера обслуживает обычные сайты при остановке Xray. Для защищённых зон он направляет запросы только в классификатор и при его недоступности возвращает ошибку или пустой ответ. Отдельные правила назначения доменов, исходящие маршруты и реальные IP сверяют с точным набором selectors, который отправляет панель.
- Кешированные синтетические адреса должны сохранять принадлежность к сервису при рестарте, обновлении и исчерпании пула. Встроенный Xray FakeDNS ограничивает число записей и вытесняет старые связи по LRU. Развёртывание с несколькими сервисами требует проверить также восстановление старой связи или блокировку пакета после потери отображения. [Описание пула Xray](https://xtls.github.io/en/config/fakedns.html)
- При остановке ядра, ошибке выбора узла, обновлении правил прошивкой, смене WAN и холодной загрузке повторяют соединения к защищённым и обычным контрольным адресам с клиента. Проверяют и уже открытые TCP/QUIC-соединения, и новые запросы. По наблюдениям на стороне WAN защищённый запрос должен прекратиться, а прямой продолжаться. Отсутствие маршрута IPv6 сегодня не заменяет теста после появления IPv6-подключения.
- Entware запускает init-скрипты после монтирования `/opt`. Прошивка вызывает `netfilter.d` после изменения таблицы. В интервале до этих событий непрерывность защиты обеспечивает только отдельное правило прошивки либо другой независимый контроль. Ускорение потоков способно обходить программную цепочку FORWARD после установки соединения, поэтому статус `check` сам по себе описывает только программные правила. [События и порядок загрузки Keenetic](https://support.keenetic.com/titan/kn-1810/en/42407-opkg-component-description.html) [Документация Linux об ускорении потоков](https://docs.kernel.org/networking/nf_flowtable.html)
